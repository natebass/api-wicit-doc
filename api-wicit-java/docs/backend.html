Backend setup

The WICit API is a Spring Boot application in api-wicit-java, built with Gradle. It serves the published WIC data to the website from PostgreSQL.

Requirements

Component Version
Java (toolchain) 27
Gradle (wrapper) 9.8.1
Spring Boot 4.1.1
Spring dependency management plugin 1.1.7
PostgreSQL 18 (any recent version works)
Liquibase 4.33.0, run by the org.liquibase.gradle plugin 3.1.0
jOOQ 3.21.7, the version Spring Boot manages, with the org.jooq.jooq-codegen-gradle plugin
springdoc-openapi 3.1.1

See Prerequisites to install the JDK.

Starters

Spring Boot 4 split the old spring-boot-starter-web into smaller starters, each with a matching test starter.

Starter What it adds
spring-boot-starter-webmvc Spring MVC and Tomcat for the REST API.
spring-boot-starter-jooq jOOQ for type-safe SQL, with a DSLContext bound to Spring's transactions.
spring-boot-starter-actuator Health checks at /actuator/health.
spring-boot-starter-validation Validation of request parameters.
springdoc-openapi-starter-webmvc-ui The OpenAPI document and Swagger UI.
spring-boot-starter-webmvc-test, spring-boot-starter-jooq-test @WebMvcTest and @JooqTest slices. Database tests use an in-memory H2 database that Liquibase builds from the schema changesets (spring-boot-starter-liquibase, tests only). Annotate them with @DatabaseTest.

Project layout

Path What it is
build.gradle Plugins, Java toolchain, dependencies, the Liquibase activity, jOOQ code generation and the docs site task.
src/generated/jooq/ jOOQ classes generated from the database schema: one class per table (such as Tables.VENDOR) and one record class per row type. Generated by ./gradlew jooqCodegen and committed; never edit them by hand.
src/main/java/org/opensac/wicitapi/ Application source, one package per dataset: vendor, product, farmersmarket, participants, redemption and dataset (file downloads). config holds CORS, OpenAPI and jOOQ settings; common holds paging and shared query conditions.
src/main/resources/application.yaml Spring configuration, with dev and prod profiles.
src/main/resources/db/changelog/ Liquibase changelogs: the schema and the CSV seed.
src/main/resources/<dataset>/ The published data files. See Data.
src/test/ Tests, DatabaseTest (the database test slice), and application-test.yaml for the H2 test database.
docs/ Source pages for this documentation site.

Each package follows the same shape: a @Repository that runs jOOQ queries against the generated table classes and maps rows to response records, a @Service that holds the logic (limits, paging), and a thin @RestController. Dependencies come in through constructors, so tests can build a service with a fake repository.

jOOQ renders table and column names without quotes (see config/JooqConfig.java). Every name in the schema is lower case, so PostgreSQL reads them the same way, and the H2 test database matches them too.

Configuration

Settings are in application.yaml. Secrets are never stored there: they come from environment variables. For local development, the API and Gradle also read a .env file in api-wicit-java. It is ignored by Git, so never commit it. Write values without quotes:

DB_URL=jdbc:postgresql://localhost:5432/app_28c3
DB_USERNAME=nateb
DB_PASSWORD=your-password
Variable Purpose
DB_URL JDBC URL of the database. The dev profile defaults to jdbc:postgresql://localhost:5432/app_28c3.
DB_USERNAME Database user. The dev profile defaults to nateb.
DB_PASSWORD Database password. No default.
SPRING_PROFILES_ACTIVE dev (the default) or prod.
PORT HTTP port in the prod profile. Defaults to 8080.

Profiles

Profile Differences
dev Database defaults for a local PostgreSQL. Allows browser requests from the Vite dev server (localhost:5173) and preview server (localhost:4173). Health details are shown.
prod Every database setting must come from the environment. Health details are hidden.

Allowed origins (CORS)

The website runs on a different origin from the API, so the API lists the origins allowed to call it under wicit.cors.allowed-origin-patterns. Every profile allows https://findwic.com, https://www.findwic.com and https://*.github.io, so forks such as opensacorg.github.io/wicit and natebass.github.io/wicit work without changes. The API is read-only and only allows GET requests.

Set up the database

  1. Create the database and user in PostgreSQL, if they do not exist.
  2. Put the connection settings in api-wicit-java/.env, as above.
  3. Create the schema and load the CSV files: 
    cd api-wicit-java
./gradlew update

The first run takes about two minutes. Later runs only reload datasets whose files changed. See how the files get into the database.

Other useful Liquibase tasks:

Command What it does
./gradlew status Lists changesets that have not run yet.
./gradlew history Lists the changesets that have run.
./gradlew update -PliquibaseContexts=schema Applies schema changes without loading data.
./gradlew dropAll Drops every table, to start over. Never run it against production.

To update the data, replace the files in src/main/resources/<dataset>/ with a newer download and run ./gradlew update.

Change the schema

  1. Add a new file under db/changelog/schema/ and include it in db.changelog-master.yaml. Never edit a schema changeset that has already run.
  2. Apply it to your local database with ./gradlew update.
  3. Regenerate the jOOQ classes from that database with ./gradlew jooqCodegen. It reads the same DB_ settings as Liquibase.
  4. Commit the changelog and the changed files in src/generated/jooq/ together.

The generated classes are committed so that building the API, and the documentation workflow, never need a database. If a query no longer compiles after regenerating, the schema change broke it.

Run, build and test

From the repository root:

Command What it does
make backend-db Creates the schema and loads the CSV files with ./gradlew update.
make backend Runs the API at localhost:8080 with bootRun.
make backend-build Compiles and packages the API, skipping tests.
make backend-test Runs the tests. They use H2 and do not need PostgreSQL.
make backend-clean Deletes the build/ folder.
make docs Builds this site with the Javadoc into api-wicit-java/build/site.

Without Make, run Gradle from api-wicit-java. Use gradlew.bat on Windows and ./gradlew on macOS and Linux:

cd api-wicit-java
./gradlew bootRun
./gradlew test
./gradlew docsSite

Endpoints

Path What it serves
/api/vendors, /api/vendors/in-bounds Authorized vendors, for the map.
/api/products Authorized products, for the food search.
/api/farmers-markets, /api/farmers Farmers and farmers' markets.
/api/participants/… Participants by county.
/api/redemptions/… Redemptions by county.
/api/datasets Downloads of the original published files.
/swagger-ui.html Interactive API reference. The OpenAPI document is at /v3/api-docs.
/actuator/health Health check, including the database connection. /actuator/health/liveness and /actuator/health/readiness are also available.

Errors are returned as RFC 9457 problem details, such as {"status":404,"title":"Not Found","detail":"…"}.

Deployment

The API runs on an AWS EC2 instance (t2.micro, us-west-2a) with PostgreSQL installed on the same machine.

  1. Build the jar with ./gradlew bootJar. It is written to build/libs/ and includes the dataset files.
  2. Load the database from your machine by pointing Liquibase at the server, for example through an SSH tunnel to port 5432: 
    DB_URL=jdbc:postgresql://localhost:5432/app_28c3 DB_USERNAME=... DB_PASSWORD=... ./gradlew update
  3. On the server, run the jar with SPRING_PROFILES_ACTIVE=prod and the DB_ variables set, for example from a systemd service. A t2.micro has 1 GB of memory, so cap the heap with -Xmx384m.
  4. Serve it over HTTPS. The website is served over HTTPS from GitHub Pages, and browsers block its requests to a plain HTTP API. Put a reverse proxy such as Caddy or nginx with a Let's Encrypt certificate in front of port 8080, on a domain name such as api.findwic.com, then set VITE_API_BASE_URL to that URL. The API honors the proxy's X-Forwarded-* headers.
  5. Point the load balancer or monitoring at /actuator/health.

Documentation site

The docsSite Gradle task generates the Javadoc and copies it to build/site/api, next to the pages from docs/. Open build/site/index.html in a browser to preview the site.

On every push to master that changes api-wicit-java/, the Deploy docs to GitHub Pages workflow builds the site and publishes it to natebass.github.io/api-wicit-doc.

Write Javadoc comments on public classes and methods. They appear in the API reference.
