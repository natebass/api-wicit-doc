Deploy the API to EC2

The API runs on an AWS EC2 instance, with PostgreSQL on the same machine. The instance serves only the backend. The website is hosted on GitHub Pages and calls the API over HTTPS.

Setting Value
Elastic IP 44.254.208.38
Public DNS name ec2-44-254-208-38.us-west-2.compute.amazonaws.com
API URL https://44.254.208.38, or https://api.findwic.com once its DNS record is set up
Database user app
Database name app_ followed by four hex characters, such as app_1a2b. These pages write it as app_xxxx.

The commands below assume Amazon Linux 2023, the ec2-user login user, and the repository cloned to /home/ec2-user/api-wicit-doc. Change the paths if yours differ.

How requests reach the API

The website is served over HTTPS, and browsers block its requests to a plain HTTP API. So Caddy listens on ports 80 and 443, gets a free certificate from Let's Encrypt, and forwards requests to the API on 127.0.0.1:8080. The API and PostgreSQL only listen on the instance itself.

Browser (GitHub Pages site)
  → https://44.254.208.38      Caddy, ports 80 and 443
  → http://127.0.0.1:8080      Spring Boot API
  → localhost:5432             PostgreSQL

Let's Encrypt does not issue certificates for *.amazonaws.com names, so the API uses the Elastic IP address instead. Certificates for an IP address last about six days. Caddy renews them automatically. To use api.findwic.com instead, see Use api.findwic.com.

1. Open the ports

In the EC2 console, edit the instance's security group so its inbound rules are:

Port Source Why
22 (SSH) Your IP only Administration.
80 (HTTP) 0.0.0.0/0 Let's Encrypt checks this port before it issues a certificate. Caddy redirects everything else to HTTPS.
443 (HTTPS) 0.0.0.0/0 The API.

Do not open 8080 or 5432.

2. Add swap

A t2.micro has 1 GB of memory, which isn't enough to run Gradle and load the data. Add 2 GB of swap:

sudo dd if=/dev/zero of=/swapfile bs=1M count=2048
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap defaults 0 0' | sudo tee -a /etc/fstab

3. Install JDK 27

Install Amazon Corretto 27 from its tarball into /opt/java. The link /opt/java/corretto-27 points to the installed version, so the service file and PATH don't change when you upgrade:

sudo dnf install -y wget
cd /tmp
wget https://corretto.aws/downloads/latest/amazon-corretto-27-x64-linux-jdk.tar.gz
sudo mkdir -p /opt/java
sudo tar -xzf amazon-corretto-27-x64-linux-jdk.tar.gz -C /opt/java
ls /opt/java

ls shows the folder the tarball created, such as amazon-corretto-27.0.1.8.1-linux-x64. Link it and put it on everyone's PATH:

sudo ln -sfn /opt/java/amazon-corretto-27.0.1.8.1-linux-x64 /opt/java/corretto-27
echo 'export JAVA_HOME=/opt/java/corretto-27
export PATH="$JAVA_HOME/bin:$PATH"' | sudo tee /etc/profile.d/java.sh
source /etc/profile.d/java.sh
java -version

Gradle runs on this JDK and uses it for the project's Java 27 toolchain. To upgrade later, extract the new tarball, point the link at the new folder, and restart the API.

4. Set up PostgreSQL

Install PostgreSQL 18, create its data folder, and start it at boot:

sudo dnf install -y postgresql18 postgresql18-server postgresql18-contrib
sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql

Create the app user and the database. Pick four hex characters for the name, and a strong password:

sudo -u postgres psql -c "create user app with password 'your-password';"
sudo -u postgres psql -c "create database app_xxxx owner app;"

By default, PostgreSQL on Amazon Linux checks local network connections with ident, which rejects passwords. The API connects over localhost with a password, so change those lines. Open the file with sudo nano /var/lib/pgsql/data/pg_hba.conf and change the host lines for 127.0.0.1/32 and ::1/128 to use scram-sha-256:

host    all    all    127.0.0.1/32    scram-sha-256
host    all    all    ::1/128         scram-sha-256

Then restart PostgreSQL and check that the app user can connect. Put your password and database name in place of PASSWORD and app_xxxx:

sudo systemctl restart postgresql
psql "postgresql://app:PASSWORD@localhost:5432/app_xxxx" -c 'select version();'

PostgreSQL only listens on localhost unless you change listen_addresses, so leave that setting alone. If the password contains characters that have a meaning in URLs, such as @, / or :, percent-encode them in this command. In the .env file below, write the password as it is.

5. Set the environment variables

The API, Gradle and systemd all read one file: api-wicit-java/.env. Git ignores it, so it is never committed. Create it:

cd ~/api-wicit-doc/api-wicit-java
nano .env

Write each value on one line, without quotes:

SPRING_PROFILES_ACTIVE=prod
DB_URL=jdbc:postgresql://localhost:5432/app_xxxx
DB_USERNAME=app
DB_PASSWORD=your-password
SERVER_ADDRESS=127.0.0.1
PORT=8080

Then make it readable only by you:

chmod 600 .env
Variable Value on EC2
SPRING_PROFILES_ACTIVE prod. Requires every database setting and hides health details.
DB_URL The JDBC URL. It has no user or password, unlike the psql URL.
DB_USERNAME app
DB_PASSWORD The app user's password.
SERVER_ADDRESS 127.0.0.1, so the API only accepts connections from Caddy on the same machine.
PORT 8080, the port Caddy forwards to.

6. Load the data

Create the schema and load the CSV files into the database. Liquibase reads the DB_ settings from .env:

cd ~/api-wicit-doc/api-wicit-java
chmod +x gradlew
./gradlew --no-daemon update

The first run downloads Gradle and the dependencies, then takes a few minutes to load the data. Check that every changeset ran:

./gradlew --no-daemon status

It should report that the database is up to date. Then check the row counts:

psql "postgresql://app:PASSWORD@localhost:5432/app_xxxx" -c "
select 'vendor' as table_name, count(*) from vendor
union all select 'authorized_product', count(*) from authorized_product
union all select 'farmers_market', count(*) from farmers_market
union all select 'wic_farmer', count(*) from wic_farmer
union all select 'participants_by_category', count(*) from participants_by_category
union all select 'participants_by_race_ethnicity', count(*) from participants_by_race_ethnicity
union all select 'redemption_by_family', count(*) from redemption_by_family
union all select 'redemption_by_participant_category', count(*) from redemption_by_participant_category;"

Every table should have rows. Later runs of ./gradlew update only reload datasets whose files changed. See Set up the database for the other Liquibase tasks. Never run ./gradlew dropAll on this server.

7. Build the API

./gradlew --no-daemon bootJar

This writes build/libs/wicit-api-0.0.1-SNAPSHOT.jar. The jar includes the dataset files. It does not need a database to build.

8. Run the API as a service

systemd starts the API at boot and restarts it if it stops. Create the service file:

sudo nano /etc/systemd/system/wicit-api.service
[Unit]
Description=WICit API
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
User=ec2-user
WorkingDirectory=/home/ec2-user/api-wicit-doc/api-wicit-java
EnvironmentFile=/home/ec2-user/api-wicit-doc/api-wicit-java/.env
ExecStart=/opt/java/corretto-27/bin/java -Xmx384m -jar build/libs/wicit-api-0.0.1-SNAPSHOT.jar
SuccessExitStatus=143
Restart=on-failure

[Install]
WantedBy=multi-user.target

-Xmx384m caps the heap so the API, PostgreSQL and Caddy fit in 1 GB. Start the service and check it:

sudo systemctl daemon-reload
sudo systemctl enable --now wicit-api
curl http://127.0.0.1:8080/actuator/health

The health check returns {"status":"UP"} once the API has connected to the database. To follow the logs, run journalctl -u wicit-api -f.

9. Serve it over HTTPS with Caddy

Caddy has no package for Amazon Linux, so download its single binary and give it a system user:

sudo curl -fL -o /usr/local/bin/caddy "https://caddyserver.com/api/download?os=linux&arch=amd64"
sudo chmod +x /usr/local/bin/caddy
caddy version
sudo groupadd --system caddy
sudo useradd --system --gid caddy --create-home --home-dir /var/lib/caddy --shell /sbin/nologin caddy
sudo mkdir -p /etc/caddy

Create /etc/systemd/system/caddy.service. This is Caddy's standard service file. It lets Caddy listen on ports 80 and 443 without running as root:

[Unit]
Description=Caddy
After=network-online.target
Wants=network-online.target

[Service]
Type=notify
User=caddy
Group=caddy
ExecStart=/usr/local/bin/caddy run --environ --config /etc/caddy/Caddyfile
ExecReload=/usr/local/bin/caddy reload --config /etc/caddy/Caddyfile --force
TimeoutStopSec=5s
LimitNOFILE=1048576
PrivateTmp=true
ProtectSystem=full
AmbientCapabilities=CAP_NET_ADMIN CAP_NET_BIND_SERVICE

[Install]
WantedBy=multi-user.target

Create /etc/caddy/Caddyfile:

{
	# Requests to an IP address carry no server name, so tell Caddy which certificate to use.
	default_sni 44.254.208.38
}

44.254.208.38 {
	# Let's Encrypt only issues IP address certificates with its short-lived profile.
	tls {
		issuer acme {
			profile shortlived
		}
	}
	encode gzip
	reverse_proxy 127.0.0.1:8080
}

Start Caddy and watch it get the certificate:

sudo systemctl daemon-reload
sudo systemctl enable --now caddy
journalctl -u caddy -f

Then check from your own computer:

curl https://44.254.208.38/actuator/health

The API reads the X-Forwarded-* headers Caddy sends, so links it generates, such as in Swagger UI at https://44.254.208.38/swagger-ui.html, use HTTPS.

If Let's Encrypt refuses the IP address certificate, use the host name 44-254-208-38.sslip.io, which resolves to the same address. Put it in place of both 44.254.208.38 lines in the Caddyfile and remove the global options block and the tls block. Caddy then gets an ordinary 90-day certificate. Many people share sslip.io's Let's Encrypt limits, so an IP address certificate or api.findwic.com is more reliable.

10. Point the website at the API

The website reads the API's address from VITE_API_BASE_URL when it is built. In the GitHub repository that publishes the website, go to Settings → Secrets and variables → Actions → Variables. Set the VITE_API_BASE_URL repository variable to https://44.254.208.38, with no trailing slash. Then run the Deploy to GitHub Pages workflow again.

The API already allows requests from https://*.github.io, so no CORS change is needed. To check it from your computer:

curl -sI -H "Origin: https://natebass.github.io" https://44.254.208.38/api/datasets | grep -i access-control-allow-origin

Update the server

After you push changes, update the server:

cd ~/api-wicit-doc
git pull
cd api-wicit-java
./gradlew --no-daemon update      # only needed if the schema or data files changed
./gradlew --no-daemon bootJar
sudo systemctl restart wicit-api

Troubleshooting

Problem What to check
The service stops at startup journalctl -u wicit-api -n 100. A missing DB_ variable or a wrong password shows up here.
Gradle or the API is killed The instance ran out of memory. Check that swap is on with swapon --show.
Caddy can't get a certificate journalctl -u caddy -n 100. Check that ports 80 and 443 are open to everyone in the security group.
The browser blocks the website's requests Open the developer console. A mixed-content error means VITE_API_BASE_URL starts with http://. A CORS error means the website's origin isn't allowed in application.yaml.

Use api.findwic.com

The findwic.com domain is managed in Route 53 in the organization's WICit AWS account. Point api.findwic.com at the Elastic IP to give the API a stable name with an ordinary 90-day certificate.

Sign in with the SystemAdministrator role

Open the organization's AWS access portal, expand the WICit account, and choose SystemAdministrator, not AdministratorAccess. Use the least access the task needs. SystemAdministrator includes full Route 53 access (route53:*) and can also edit the EC2 security group.

Add the DNS record

  1. Open Route 53 → Hosted zones and choose findwic.com. If the zone isn't there, the domain's DNS is hosted somewhere else. Run dig NS findwic.com to see which name servers answer for it, and add the record there.
  2. Choose Create record and enter:
    Field Value
    Record name api
    Record type A
    Alias Off. An Elastic IP isn't an alias target.
    Value 44.254.208.38
    TTL 300
    Routing policy Simple routing
  3. Choose Create records.

No other record is needed. Don't add an AAAA record unless the instance has an IPv6 address.

Check the CAA records

CAA records list which certificate authorities may issue certificates for the domain. Check for them:

dig +short CAA findwic.com

If this prints nothing, Let's Encrypt is allowed and there is nothing to do. If it prints records and none of them is 0 issue "letsencrypt.org", add that value to the existing CAA record for findwic.com in the hosted zone.

Check that the name resolves

dig +short api.findwic.com

It should print 44.254.208.38, usually within a few minutes.

Or add it with the AWS CLI

To use the CLI, set up a profile for the same account and role through the access portal, then sign in:

aws configure sso --profile wicit-sysadmin
aws sso login --profile wicit-sysadmin

Find the hosted zone ID, then create or update the record:

aws route53 list-hosted-zones-by-name --dns-name findwic.com --profile wicit-sysadmin \
  --query 'HostedZones[0].Id' --output text

aws route53 change-resource-record-sets --profile wicit-sysadmin \
  --hosted-zone-id ZONE_ID \
  --change-batch '{
    "Comment": "WICit API on EC2",
    "Changes": [{
      "Action": "UPSERT",
      "ResourceRecordSet": {
        "Name": "api.findwic.com",
        "Type": "A",
        "TTL": 300,
        "ResourceRecords": [{"Value": "44.254.208.38"}]
      }
    }]
  }'

Put the ID from the first command, without the /hostedzone/ prefix, in place of ZONE_ID.

Serve the domain from Caddy

Add a site block for the domain to /etc/caddy/Caddyfile. Keep the IP address block until the website has switched, so both addresses work in the meantime:

{
	default_sni 44.254.208.38
}

api.findwic.com {
	encode gzip
	reverse_proxy 127.0.0.1:8080
}

44.254.208.38 {
	tls {
		issuer acme {
			profile shortlived
		}
	}
	encode gzip
	reverse_proxy 127.0.0.1:8080
}

Reload Caddy and check the new name from your computer:

sudo systemctl reload caddy
curl https://api.findwic.com/actuator/health

If Caddy can't get the certificate, check that the DNS record resolves and that ports 80 and 443 are open.

Switch the website

Set the VITE_API_BASE_URL repository variable to https://api.findwic.com and run the Deploy to GitHub Pages workflow again, as in step 10. No CORS change is needed: the API allows the website's origins, and its own host name doesn't matter for CORS.

Once the website uses the new name, you can remove the global options block and the 44.254.208.38 block from the Caddyfile and reload Caddy.
